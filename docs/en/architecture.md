# Architecture

[Русский](../ru/architecture.md) · **English**

Guides: [overview](overview.md), [layout](layout.md), [graph](graph.md), [slices](slices.md).

Pipeline: `parse → compile → layout → graph → build → render`.

```mermaid
flowchart LR
  xlsx[source.xlsx] --> parse
  parse --> compile
  compile --> layout
  layout --> graph
  graph --> build
  build --> json[context.json]
  graph --> gjson[graph.json]
  gjson --> gmd[graph.md]
  json --> render
  render --> md[context.md]
```

## Layers

1. **Raw** (`raw/cells.parquet`, `raw/cell_presence.parquet`, `raw/workbook.json`): cells, formulas, cached values, formats, comments, defined names, and every `<c>` marked `populated` or `styled_blank`. OOXML via lxml with zip-slip / bomb / encryption guards. An OLE2 upload is sniffed by its directory: `EncryptionInfo` is `encrypted_workbook`, a `Workbook` stream is legacy `.xls`. That `source.xls` is converted once into `source.xlsx` through the `XlsConverter` port (adapter: LibreOffice headless, `adapters/soffice.py`, with a timeout). Cached values are then copied from the `.xls` (`excel/xls_cache.py`, `xlrd`) so the pipeline reads the Excel cache. A failure is `conversion_failed`.
2. **Formulas** (`ir/cells.parquet`, `ir/edges.parquet`, `ir/cell_edges.parquet`, stamp `ir/compile.json`): templates, AST, formula-level edges, and expanded cell→cell edges (`dangling` / `dangling_reason` / `status` / `reason` / `evidence` / `range_ref` / `truncated`). A shared formula group is parsed from its master cell; the other cells keep the shifted A1 text and the same template and edges. Edges are expanded once per compile. `col_offset` and `period_lag` stay empty in `cell_edges`. Named ranges such as `DS_Drawn_C:DS_Drawn_N` stay unresolved. Unsupported formulas are marked `unparsed`. A range may repeat the sheet qualifier on the right (`SUM(TBA!$D$10:'TBA'!D10)`). Binary templates keep operator parentheses, e.g. `(1+Sub_Growth_M)^(R[-4]C[0]-1)`. A blank on a parsed sheet is `empty` / `actual_blank_cell`. A populated XML cell missing from the index is `parser_resolution_failure`.
3. **Layout** (`layout.json`): statement-like blocks, period axes (calendar years/dates **or** model-year indices `Y1..Yn`), or `params` blocks when there is no axis; grain, label span, row kinds, section path, and role-tagged non-period cells. Formula-shape relations (`alias`, `aggregate`, `difference`, `roll_forward`) are computed here from the layout and the cell IR. Details: [layout.md](layout.md).
4. **Graph** (`graph.json` and `graph.md`, schema `1.7.0`): summary plus one `links[]` record per formula cell (`cell`, A1 `formula` once, `formula_class`, `refs`, `row_key`, `period_id`). `formula_class` is one of `same_period`, `cross_period`, `aggregation`, `rollforward`, `conditional`, `hardcoded`. `row_key` and `period_id` are null outside layout. `SUM(J9:J12)` stays one range ref. `nodes` and `edges` are cell-level parquet counts, not `len(links)`. The summary also carries workbook `iterate`, cycle classes (`iterative_ok` vs `unexpected`) with optional `breakers`, `circularity_hints` when SCC is empty, and `dangling_classes`. Verified blanks (`empty_range_member`, `empty_ref`) are `node_type=empty` in `ir/graph_index.parquet` and are not `graph.dangling`; they are not members of `links`. The index columns are `node_id`, `sheet`, `addr`, `row_key`, `period_id`, `node_type`. Formula expansion stays in `ir/cell_edges.parquet` and is not rewritten by the graph stage. `col_offset` and `period_lag` are published in `ir/graph_edges.parquet`. Anchors and AST stay in `ir/cells.parquet`. Trace reads `graph_edges` and is ready only when `graph.json` exists. Trace is on demand: `GET /v1/context-jobs/{id}/graph/trace` and `GET .../graph/trace.md`. Details: [graph.md](graph.md). There is no `graph-edges.json`, `graph-dangling.json`, `formulas.json`, or `report.json`.
5. **Context** (`context.json`, schema `1.14.0`): canonical `ContextDocument`. `axes` holds the period keys, `flags` from 0/1 flag rows on the axis that contains those rows, and `calendar_year` on a calendar book. A FAST Start/End date ruler is that one axis: the period key comes from the end date, and each period may carry `start_date` / `end_date` (ISO). A column with only an end date (`Model_start`) is a `stub`, not a period. A later header whose formula points at the date row (`=YEAR(M7)`) aliases the same axis. A repeated year banner over a finer axis is `group_key` on that axis, not its own axis. A later section header with the same columns and keys reuses that axis. `context.json` omits empty flags and a calendar year that repeats the period key. A marker on a period column is recognized, and a repeated key with different variant markers is `<period_key>@<marker>` (`casefold`). Schema `1.14.0` adds no separate field for the marker. Every layout row lives once inside its block (`blocks[].rows`): `row_key`, label, `label_path`, kind, hints, one formula fingerprint, and `series` aligned to each `axis_id` (cached string or `null`). Flat `values` mirror the first series. `value_statuses` (`cached`, `empty`, `zero_explicit`, `not_applicable`) and `normalized_values` are flat lists of the same length. `scale_factor` is the numeric multiplier (`1`, `1000`, `1000000`, `1000000000`); `hints.scale` stays the token `unit` / `k` / `m` / `bn`. A column that is not a value column is `not_applicable`. An empty cell on a non-series kind is `not_applicable`. An explicit `0` stays `zero_explicit`. There is no top-level second row catalog and no per-cell `source` or `number_format`. `graph` is a pointer plus counts (`iterate`, `dangling`, `empty_range_members`). `block.kind` is `timeline` or `params`; a params block stores column roles, not a second copy of the year axis. A downstream answer does not read this document as a join problem. The prompt gets one observation (row × period): the label, the cached value as a string, unit hints, formula text, a short precedent list, a derived cell citation, and a copy of that axis period's `flags` / `group_key`. That projection is not written into schema `1.14.0`. Role cells carry `header` (Start, End, Live Case, Min). A numeric scalar left of the ruler is a `fact`. A total or stub column is not a period, so its graph link has `period_id=null`. AST stays in `ir/cells.parquet`, and there is still no per-cell `source`. Contract: [slices.md](slices.md).
6. **Markdown** (`context.md`, `graph.md`): the same documents as the JSON, rendered as tables and lists. A row shows Unit, then the formula. Period cells show the cache and `[Sheet!A1]`; a scaled number also shows the base-unit amount (`1.5 (1500)`). `empty` and `n/a` are written out. `graph.md` adds a Class column on the links table. Do not merge cells, formula AST, or the dependency graph into either Markdown file. The context header reports **content completeness** (`1.00 (rows/rows layout rows)`), then `## Axes` once per axis. The axis is one table with periods as columns: the header row is the axis id and the period keys (`| PF Model!r9 | 2021 | 2022 | 2032 |`), and `Start`, `End`, `Group`, `Calendar`, and `Flags` are rows under it. A block table adds `Path` (`label_path`) and `Cells` (`L total: -86400`, `G Start: 01.01.2024`). There is no Concept column. A params scenario table prints `Live Case (L)` and `Case 1 (N)` as columns. An attribute row with no values is hidden, so a year axis with no dates, group, or flags is the header alone. A regular month grid collapses to one column per year (`| Output!r6 | 2020 | 2021 |`, then `| Periods | 2020-01 .. 2020-12 | ... |`). A block with several axes lists `Axes:` and prints one value grid per series. Every block, every row, and every period value is included. Each row shows `row_key`. Period headers show the period key and column letter (`Y23 (AA)`, params `Values (D)`). Block `relations` are listed with the same `row_key`. Params blocks are `## Parameters / {sheet}`. There is no 16-column or 80-row cap and no row navigator. `graph.md` repeats summary, empty-cell classes, cycles, circularity hints, and every link with `row_key` and `period_id`. Trace markdown repeats the trace nodes and edges.

## Layout row kinds

Each body row gets `kind` and `section_path` from structure, not from a label dictionary of business meanings:

| kind | Meaning |
| --- | --- |
| `fact` | Period cells have numbers or formulas. Period series in context. |
| `abstract` | Section header: label without period values. Parent of following facts. |
| `index` | Counter `Week #` / `Month #`: a run of `0\|1..n` on the axis and a counter label, or no formulas in the period cells. Kept on the block row. |
| `helper` | Check / tie-out / placeholder (`Spare`, `None`). Values stay on the same row. |
| `flag` | Binary timing rows (≥90% of values in `{0, 1}`, or a `flag` token) and the params scenario selector (`Scenario Chosen`, `Live Case`). Price cases (`Mid case`, `Applied`) stay `fact`. |

A published job is `succeeded`.

Weekly dates keep distinct `YYYY-MM-DD` keys. Grain `week` / `biweek` does not collapse them to months. Relative project-finance axes use keys `Y1` / `Q1` / `M1` / `P1` and grain `model_*`; they are not calendar keys. After context build, 0/1 flag rows attach to the axis whose rows contain them as `flags`. Week and biweek axes are not collapsed when keys repeat. Calendar books without those flags get `calendar_year` from the period key. Flag rows stay on the block with their `kind`.

On a sheet, a short date pair that sits entirely left of the widest timeline is not a second block. Row labels are taken from a **span** of text columns left of the axis (not `min(col)`), so section headers in col 2 and articles in col 4 still become `abstract` + `fact`. Each `LayoutRow` may store its own `label_col` for provenance. Columns between the label span and the period axis are role-tagged (`total` / `unit` / `value`). Sheets without an axis become `params` or are rejected as prose/nav — they do not inflate completeness.

Hints are written from the label and the unit cell: `unit`, `unit_per`, `currency`, `scale`. `k£` in a label or Units cell is money, GBP, and `k`. `тыс. руб.` / `млн ₽` / `млрд руб.` is money, RUB, and `k` / `m` / `bn`; `руб.` alone is `unit`. `RURm` / `mRUB` / `RUB mn` is money, RUB, and `m`; `RUR` alone is RUB at `unit`; `USD bn`, `EURk`, and `RUB'000` carry `bn` / `k`. A unit caption in the period-header label applies to the block. A unit row inside a section applies until the next section. A unit cell on the row itself wins. A currency known only from a number format (`[$₽-419]`) leaves `scale` empty; `[$-419]` names no currency.

## Storage

`data/shared/books/{job_id}/` holds source, raw, formula IR (`cells`, `edges`, `cell_edges`, `compile.json`), and layout. `data/sessions/{session}/jobs/{job_id}/` holds context, graph, meta, plus `ir/graph_edges.parquet` and `ir/graph_index.parquet`. `job_id` is the SHA-256 of the string `context:` plus the workbook `content_sha256`, so the directory name is not the file hash. The session name is `SESSION_ID`, default `local`. Parquet is written with PyArrow. A run keeps the row lists it just built and reads `ir/*.parquet` again only on a later process, when `ir/compile.json` still matches. Swap the store adapter for object storage without changing the pipeline.

`PARSE_STREAMING` (default true) reads each sheet with iterparse, clears each row, and writes raw cells from column lists. That raw parquet stays one row group and byte-identical. `PARQUET_ROW_GROUP_ROWS` (default 65536, `0` for one group) batches formula IR and graph parquet; file bytes change only when a group is smaller than the table, and the values stay the same. `JSON_STREAM` (default true) uses `json.dump` for context and job JSON. `COMPILE_STRING_POOL` (default true) is a compile-local pool of node ids, dropped after compile, not `sys.intern`. `COMPILE_AST_ZLIB` (default true) keeps AST JSON compressed until relations. `GRAPH_STREAM` (default true) writes cell edges as column batches, enriches those row groups, and streams `graph.json` and `graph.md` without a second in-memory edge list. `LAYOUT_COLUMNAR_FACTS` (default true) reads indent and outline in Arrow and skips the dict list when every value is zero; `layout_cells_read` is still logged. `JOB_MALLOC_ARENA_MAX` (default 2, `0` disables) is set on the spawned job child. `JOB_MALLOC_TRIM` (default true) calls `malloc_trim` after each stage and does nothing when libc has no such function. Preflight uses the streaming coefficients while `PARSE_STREAMING`, `GRAPH_STREAM`, and `COMPILE_AST_ZLIB` are on, and `JOB_ESTIMATE_UNSTREAMED_*` when any of those three is off.

Publisher stages are `compile`, `layout`, `graph`, `publish`. A change in `layout` rebuilds the graph and the published documents and keeps `raw/` and formula IR.

## API

Each accepted workbook starts a spawned process whose main thread runs the full pipeline. The child calls the same `configure_logging`, so `stage_done` and `job_reuse` show up on the container stdout. A repeat POST of a finished book logs `job_reuse` and does not start a process. The API logs `http_start` and `http_done` for every request except `/healthz`. `finance-context build` stays one process. `MAX_CONCURRENT_JOBS` (default 2) caps how many children this API process runs. Each child has an RSS budget: the cgroup limit minus `JOB_MEMORY_API_RESERVE_FRACTION` (default 0.25) split across those slots, or `JOB_MEMORY_BUDGET_BYTES` when that is set. A configured cap under `JOB_MEMORY_FLOOR_BYTES` (default 128 MiB) refuses the job and is not raised. A derived share under that floor is kept. With no cgroup limit and no env cap, the budget is `JOB_MEMORY_DEFAULT_BUDGET_BYTES` (default 1536 MiB) and a warning is logged. The estimate is `JOB_ESTIMATE_BASE_BYTES` plus per-formula, per-expanded-cell, and per-present-cell terms. `JOB_MEMORY_PREFLIGHT_REFUSAL` (default true) turns the estimate refusal on. `JOB_MEMORY_WATCH_INTERVAL_SEC` (default 0.2) is how often the parent samples the child. `RANGE_EXPAND_CAP` (default 2000) bounds one rectangle. Compose sets a 4 GiB container limit; a Kubernetes pod needs `resources.limits.memory: 4Gi` (this repo ships no manifest). The parent kills a child whose resident set exceeds its RSS budget, and that job fails with `workbook_too_large`. A book whose formula and range estimate is already over it fails with `workbook_too_large` before compile, and a `MemoryError` in the child uses the same code. The child sets `oom_score_adj` to `JOB_OOM_SCORE_ADJ` (default 1000) when the kernel allows it. A second POST while that process is alive does not start another. A second POST of a finished workbook returns the snapshot when `publisher` matches. A different `publisher` stops the old process and starts a new one; a missing stamp does not stop it. The new run deletes only the stale tail in `meta.stages` (`compile`, then `layout`, `graph`, `publish`). No stage map keeps the old tail: layout and the published documents, while parse and formula IR stay. `compile` also deletes `raw/` and formula IR. `publish` rewrites context and leaves the graph. On startup, and on GET when the process is gone, a job still `queued` or `running` is marked `failed` with `error` `process_lost` and is not started again. Status comes from `meta.json` on disk. `GET /readyz` field `queue` is `in_process`, and `jobs` is the number of live children. `finance-context serve` starts uvicorn with `workers=1`: job processes are children of this API process. Statuses a new job writes: `queued`, `running`, `succeeded`, `failed`. An older finished snapshot may still say `degraded` or `needs_input`; the poller treats those as done.

`scripts/run.sh` only polls HTTP. Its `JOB_TIMEOUT_SEC` defaults to 300 when unset and does not stop the child. The server stops the child after Settings `job_timeout_sec` (default 3600, often set in `.env`). `scripts/check-graph.py` checks schema `1.7` for the graph and `1.14` for context.

Catalog filters are `q`, `sheet`, `limit`, `offset`. Observation selectors are repeatable `row_key` or `q`. Trace `from` is a cell address, a `row_key`, or a label.
