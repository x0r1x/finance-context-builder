# Архитектура

[English](../en/architecture.md) · **Русский**

Гайды: [обзор](overview.md), [layout](layout.md), [граф](graph.md), [срезы](slices.md).

Пайплайн: `parse → compile → layout → graph → build → render`.

```mermaid
flowchart LR
  xlsx[source.xlsx] --> parse
  parse --> compile
  compile --> layout
  layout --> graph
  graph --> build
  build --> json[context.json]
  graph --> gjson[graph.json]
  gjson --> gmd[graph.md]
  json --> render
  render --> md[context.md]
```

## Слои

1. **Raw** (`raw/cells.parquet`, `raw/cell_presence.parquet`, `raw/workbook.json`): ячейки, формулы, кэш, форматы, комментарии, именованные диапазоны и каждый `<c>` с пометкой `populated` или `styled_blank`. OOXML через lxml, с защитой от zip-slip, бомбы и шифрования. OLE2-файл распознаётся по каталогу: `EncryptionInfo` — `encrypted_workbook`, поток `Workbook` — старый `.xls`. Такой `source.xls` один раз конвертируется в `source.xlsx` через порт `XlsConverter` (адаптер — LibreOffice headless, `adapters/soffice.py`, с таймаутом); сбой — `conversion_failed`.
2. **Формулы** (`ir/cells.parquet`, `ir/edges.parquet`, `ir/cell_edges.parquet`, штамп `ir/compile.json`): шаблоны, AST, рёбра уровня формулы и раскрытые рёбра ячейка→ячейка (`dangling` / `dangling_reason` / `status` / `reason` / `evidence` / `range_ref` / `truncated`). Общая группа формул разбирается по мастер-ячейке; остальные ячейки хранят сдвинутый текст A1 и тот же шаблон и рёбра. Рёбра раскрываются один раз на compile. `col_offset` и `period_lag` в `cell_edges` пустые. Именованные диапазоны вроде `DS_Drawn_C:DS_Drawn_N` остаются неразрешёнными. Неподдержанная формула помечается `unparsed`. Диапазон может повторить квалификатор листа справа (`SUM(TBA!$D$10:'TBA'!D10)`). Бинарные шаблоны сохраняют скобки операторов, например `(1+Sub_Growth_M)^(R[-4]C[0]-1)`. Пустая ячейка разобранного листа — `empty` / `actual_blank_cell`. Заполненная XML-ячейка, которой нет в индексе, — `parser_resolution_failure`.
3. **Layout** (`layout.json`): блоки, похожие на отчёт, оси периодов (календарные годы/даты **или** индексы модельного года `Y1..Yn`) либо блоки `params`, если оси нет; grain, span подписей, виды строк, путь секции и role-ячейки вне периодов. Relations по форме формулы (`alias`, `aggregate`, `difference`, `roll_forward`) и структурное исключение считаются здесь из layout и IR ячеек. Подробности: [layout.md](layout.md).
4. **Граф** (`graph.json` и `graph.md`, схема `1.7.0`): сводка и одна запись `links[]` на формульную ячейку (`cell`, A1 `formula` один раз, `formula_class`, `refs`, `row_key`, `period_id`). `formula_class` — одно из `same_period`, `cross_period`, `aggregation`, `rollforward`, `conditional`, `hardcoded`. `row_key` и `period_id` равны null вне layout. `SUM(J9:J12)` остаётся одной ссылкой на диапазон. `nodes` и `edges` — счётчики parquet на уровне ячеек, не `len(links)`. Сводка также несёт `iterate` книги, классы циклов (`iterative_ok` против `unexpected`) с необязательными `breakers`, `circularity_hints`, когда SCC пуст, и `dangling_classes`. Проверенные пустые ячейки (`empty_range_member`, `empty_ref`) имеют `node_type=empty` в `ir/graph_index.parquet` и не входят в `graph.dangling` и в `links`. Колонки индекса: `node_id`, `sheet`, `addr`, `row_key`, `period_id`, `node_type`. Раскрытие формул остаётся в `ir/cell_edges.parquet` и стадия графа его не переписывает. `col_offset` и `period_lag` публикуются в `ir/graph_edges.parquet`. Якоря и AST остаются в `ir/cells.parquet`. Trace читает `graph_edges` и готов только когда есть `graph.json`. Trace по запросу: `GET /v1/context-jobs/{id}/graph/trace` и `GET .../graph/trace.md`. Подробности: [graph.md](graph.md). Файлов `graph-edges.json`, `graph-dangling.json`, `formulas.json` и `report.json` нет.
5. **Context** (`context.json`, схема `1.14.0`): канонический `ContextDocument`. Фазы модели живут только в `axes` (`period_key` с `phase` / `phase_year` / `flags` из 0/1 flag-строк на той оси, в чьих строках они лежат, либо `calendar_year` у календарной книги). Линейка дат FAST Start/End — эта одна ось: ключ периода берётся из end date, у периода могут быть `start_date` / `end_date` (ISO). Колонка только с end date (`Model_start`) — `stub`, не период. Более поздняя шапка, чья формула указывает на строку дат (`=YEAR(M7)`), — alias той же оси. Повторённый год над более мелкой осью — `group_key` этой оси, не отдельная ось. Шапка следующей секции с теми же колонками и ключами переиспользует эту ось. `context.json` не пишет пустую `phase`, пустой `flags` и `calendar_year`, если год уже в ключе. Каждая строка layout живёт один раз в своём блоке (`blocks[].rows`): `row_key`, лейбл, `label_path`, kind, `disposition`, `exclusion_reason`, hints, один fingerprint формулы и `series` по каждому `axis_id` (строка кэша или `null`). Плоские `values` повторяют первую серию. `value_statuses` (`cached`, `empty`, `zero_explicit`, `not_applicable`) и `normalized_values` — плоские списки той же длины. `scale_factor` — числовой множитель (`1`, `1000`, `1000000`, `1000000000`); `hints.scale` остаётся токеном `unit` / `k` / `m` / `bn`. `period_position` и `aggregation` стоят на строке рядом с `hints.time_semantics`. Пустая операционная строка в периоде строительства — `not_applicable`; явный `0` остаётся `zero_explicit`. У обычной строки, включая abstract-заголовок, `disposition` равен null. Исключённая строка — та же строка с `disposition=excluded`, не второй каталог. Верхнего второго каталога строк нет, нет per-cell `source` и `number_format`. `graph` — указатель и счётчики (`iterate`, `dangling`, `empty_range_members`). Фаза не копируется в `blocks[].periods`. `block.kind` — `timeline` или `params`; блок params хранит роли колонок, не вторую копию годовой оси. Ответ даунстрима не читает этот документ как задачу соединения таблиц. В промпт попадает одно наблюдение (строка × период): подпись, кэш строкой, hints единицы, текст формулы, короткий список прецедентов, вычисленная ссылка на ячейку и копия `phase` / `phase_year` / `flags` / `group_key` этого периода оси. Эта проекция не пишется в схему `1.14.0`. У role-ячеек есть `header` (Start, End, Live Case, Min). Числовой скаляр слева от линейки — `fact` с `period_position=instant` и `aggregation=none`, поэтому Markdown Time — `instant/instant/none`. Статическая ставка сохраняет семантику `rate` и печатается как `rate/instant/none`. Заполненный годовой поток остаётся `flow/during_period/sum`. Колонка total или stub — не период, поэтому у её link `period_id=null`. Фаза остаётся в `axes`, AST — в `ir/cells.parquet`, per-cell `source` по-прежнему нет. Контракт: [slices.md](slices.md).
6. **Markdown** (`context.md`, `graph.md`): те же документы, что JSON, таблицами и списками. Строка показывает Unit, затем Time (`stock/end/last`), затем формулу. Ячейка периода показывает кэш и `[Sheet!A1]`; у масштабированного числа ещё сумма в базовых единицах (`1.5 (1500)`). `empty` и `n/a` пишутся явно. `graph.md` добавляет колонку Class в таблицу links. Ячейки, AST формул и граф зависимостей в Markdown не сливаются. Шапка context сообщает **полноту контента** (`1.00 (rows/rows layout rows)`), затем `## Axes` по одному разу на ось. Ось — одна таблица, периоды колонками: шапка — id оси и ключи периодов (`| PF Model!r9 | 2021 | 2022 | 2032 |`), под ней строки `Start`, `End`, `Group`, `Phase`, `Phase year`, `Calendar` и `Flags`. Таблица блока добавляет `Path` (`label_path`) и `Cells` (`L total: -86400`, `G Start: 01.01.2024`). Колонки Concept нет. Таблица сценариев params печатает `Live Case (L)` и `Case 1 (N)` колонками. Строка атрибута без значений скрыта, поэтому годовая ось без фаз — только шапка. Регулярная месячная сетка схлопывается в одну колонку на год (`| Output!r6 | 2020 | 2021 |`, затем `| Periods | 2020-01 .. 2020-12 | ... |`). Блок с несколькими осями пишет `Axes:` и одну сетку значений на серию. Каждый блок, каждая строка и каждое значение периода включены. У каждой строки есть `row_key`. Заголовок периода показывает ключ и букву колонки (`Y23 (AA)`, у params `Values (D)`). `relations` блока перечислены с тем же `row_key`. Блоки params — `## Parameters / {sheet}`. Потолка в 16 колонок или 80 строк и навигатора строк нет. `graph.md` повторяет сводку, классы пустых ячеек, циклы, подсказки цикличности и каждый link с `row_key` и `period_id`. Markdown trace повторяет узлы и рёбра обхода.

## Виды строк layout

У строки тела есть `kind` и `section_path` из структуры, не из словаря бизнес-смыслов:

| kind | Смысл |
| --- | --- |
| `fact` | В ячейках периода числа или формулы. Серия периодов в context. `disposition` равен null, пока структурное правило не исключит строку. |
| `abstract` | Заголовок секции: подпись без значений периода. Родитель следующих fact. `disposition` равен null. |
| `index` | Счётчик `Week #` / `Month #`: прогон `0\|1..n` на оси и подпись счётчика, либо в ячейках периода нет формул. Остаётся строкой блока. |
| `helper` | Check / сверка / заполнитель (`Spare`, `None`). `disposition=excluded`, `exclusion_reason` `helper` или `check`. Значения остаются на той же строке. |
| `flag` | Бинарные строки времени (≥90% значений в `{0, 1}` или токен `flag`) и селектор сценария params (`Scenario Chosen`, `Live Case`). Ценовые кейсы (`Mid case`, `Applied`) остаются `fact`. `disposition=excluded`, `exclusion_reason=flag`. |

Опубликованная джоба — `succeeded`.

Недельные даты сохраняют разные ключи `YYYY-MM-DD`. Grain `week` / `biweek` не схлопывает их в месяцы. Относительные оси project finance используют ключи `Y1` / `Q1` / `M1` / `P1` и grain `model_*`; это не календарные ключи. После сборки context 0/1 flag-строки крепятся к той оси, в чьих строках они лежат: `phase` — `construction` или `operation`, `phase_year` считает внутри прогона, оверлеи вроде repayment остаются в `flags`. Оси week и biweek не схлопываются, когда ключи повторяются. Календарная книга без этих флагов получает `calendar_year` из ключа периода и `phase=null`. Flag-строки остаются в блоке с `disposition=excluded`.

На листе короткая пара дат целиком слева от самой широкой оси — не второй блок. Подписи строк берутся из **span** текстовых колонок слева от оси (не `min(col)`), поэтому заголовок секции в колонке 2 и статья в колонке 4 всё ещё становятся `abstract` + `fact`. У `LayoutRow` может быть свой `label_col` для происхождения. Колонки между span подписи и осью периодов получают роли (`total` / `unit` / `value`). Лист без оси становится `params` или отбрасывается как проза/навигация — в полноту он не входит.

Hints пишутся из подписи и ячейки единицы: `nature`, `time_semantics`, `unit`, `unit_per`, `currency`, `scale`, `sign`. `k£` в лейбле или ячейке Units — money, GBP и `k`. `тыс. руб.` / `млн ₽` / `млрд руб.` — money, RUB и `k` / `m` / `bn`; просто `руб.` — `unit`. Валюта только из числового формата (`[$₽-419]`) оставляет `scale` пустым; `[$-419]` валюты не задаёт.

## Хранение

`data/shared/books/{job_id}/` хранит source, raw, formula IR (`cells`, `edges`, `cell_edges`, `compile.json`) и layout. `data/sessions/{session}/jobs/{job_id}/` хранит context, graph, meta, а также `ir/graph_edges.parquet` и `ir/graph_index.parquet`. `job_id` — это SHA-256 строки `context:` и `content_sha256` книги, поэтому имя каталога не совпадает с хэшем файла. Имя сессии — `SESSION_ID`, по умолчанию `local`. Parquet пишет PyArrow. Прогон держит только что собранные списки строк и читает `ir/*.parquet` снова только в другом процессе, когда `ir/compile.json` всё ещё совпадает. Адаптер хранилища можно заменить на object storage, не меняя пайплайн.

Стадии publisher: `compile`, `layout`, `graph`, `publish`. Смена `layout` пересобирает граф и опубликованные документы и сохраняет `raw/` и formula IR.

## API

Каждая принятая книга стартует дочерний процесс, чей главный поток прогоняет весь пайплайн. Ребёнок вызывает тот же `configure_logging`, поэтому `stage_done` и `job_reuse` видны в stdout контейнера. Повторный POST готовой книги пишет `job_reuse` и процесс не стартует. API пишет `http_start` и `http_done` на каждый запрос, кроме `/healthz`. `finance-context build` остаётся одним процессом. `MAX_CONCURRENT_JOBS` (по умолчанию 2) ограничивает, сколько детей держит этот процесс API. Второй POST, пока процесс жив, ещё один не стартует. Второй POST готовой книги возвращает снимок, когда `publisher` совпал. Другой `publisher` останавливает старый процесс и стартует новый; пустой штамп его не останавливает. Новый прогон удаляет только устаревший хвост в `meta.stages` (`compile`, затем `layout`, `graph`, `publish`). Без карты стадий старый хвост — layout и опубликованные документы, parse и formula IR остаются. `compile` также удаляет `raw/` и formula IR. `publish` переписывает context и оставляет graph. На старте и на GET, когда процесса уже нет, джоба в `queued` или `running` помечается `failed` с `error` `process_lost` и заново не стартует. Статус берётся из `meta.json` на диске. Поле `queue` у `GET /readyz` — `in_process`, `jobs` — число живых детей. `finance-context serve` запускает uvicorn с `workers=1`: процессы джоб — дети этого процесса API. Статусы, которые пишет новая джоба: `queued`, `running`, `succeeded`, `failed`. Старый готовый снимок может ещё говорить `degraded` или `needs_input`; опрос считает их законченными.

`scripts/run.sh` только опрашивает HTTP. Его `JOB_TIMEOUT_SEC` по умолчанию 300, если не задан, и ребёнка не останавливает. Сервер останавливает ребёнка по Settings `job_timeout_sec` (по умолчанию 3600, часто задан в `.env`). `scripts/check-graph.py` проверяет схему `1.7` у графа и `1.14` у context.

Фильтры каталога: `q`, `sheet`, `disposition`, `limit`, `offset`. Селекторы наблюдений: повторяемый `row_key` или `q`. `from` у trace — адрес ячейки, `row_key` или подпись.
